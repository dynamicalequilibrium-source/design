# 설계 결정

## 2026-10-22 · 첫 서버 저장 기능

- 기준: 사용자가 제공한 업무 바통 설계계획서 v0.4의 F02/F03 및 12·17·18·22절. 전체 서비스를 한 번에 교체하지 않고 기존 React/Vite/TypeScript 화면에서 질문 저장을 먼저 연결한다. Next.js 전환은 별도 결정으로 남긴다.
- 대상: GitHub `dynamicalequilibrium-source/design`의 `main`. 별도의 미커밋 로컬 디자인은 수정하지 않는다.
- 변경 파일 계획: `src/App.tsx`, 질문 UI·본문·헤더 컴포넌트, `src/api.ts`, `vite.config.ts`, `server/`, 실행 및 테스트 문서. 화면→API→SQLite 저장과 새로고침을 검증한다.
- 질문 레코드의 키는 전역 문장 ID 대신 고유 질문 ID다. UI는 documentId/blockId/sentenceId를 함께 비교한다. 동일 문장에 새 질문을 추가해도 기존 질문을 덮어쓰지 않는다.
- 서버는 고정 샘플 사용자만 발급한다. 브라우저가 지정한 역할·검토 상태·작성자를 저장에 사용하지 않는다. 이것은 F11 문서별 ACL 완료를 의미하지 않는다.
- 원문과 게시 버전은 이 단계에서 읽기 전용이다. 서버가 인용문 전체를 확인하고 문장 기준 문자 범위를 저장한다. 버전 변경과 재연결은 다음 단계다.
- 기존 샘플 답변의 검토 배지를 초기화한다. 사용자 자유 입력 근거는 출처 검증 전 메모로 저장한다. 검토 승인 및 출처 확인 기능이 없는 상태에서 검토 완료를 만들지 않는다.
- 중복 쓰기는 Idempotency-Key와 SQLite 트랜잭션으로 제어한다. 같은 키의 다른 요청은 409다. 여러 질문에 대한 동시 요청은 각 서버 트랜잭션이 최신 레코드를 읽고 수정한다.
- 기존 esbuild 0.25 범위와 Vite 8의 peer 요구가 충돌했다. esbuild를 0.28 범위로 맞추고 검증한 npm 잠금 파일을 추가한다. 오래된 bun 잠금 파일은 제거하고 npm을 실행 기준으로 통일한다.
- 질문·답변 초안은 고정 샘플 사용자/문서/문단/문장/입력 종류를 포함하는 브라우저 키에 저장한다. 서버 저장과 별개다.
